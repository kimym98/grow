# PRD: Grow 데스크탑 앱

## 1. 개요

### 1.1 제품 소개
노션(Notion)과 유사한 데스크탑 앱 형태로 제공되는 Grow 서비스. IT 취업 준비생이 필요로 하는 정보 수집, 서류 첨삭, 면접 준비, 일정관리를 하나의 앱에서 처리한다.

### 1.2 목표
- 취업 준비 과정에서 흩어져 있는 작업(공고 탐색, 뉴스 확인, 자소서 작성, 면접 대비, 일정 관리)을 한 곳으로 통합
- 데스크탑 앱으로 먼저 출시하고, 이후 모바일 앱까지 확장

### 1.3 대상 사용자
- IT 직군(개발/기획/디자인 등) 취업 준비생
- 채용 공고 탐색, 서류 작성, CS 지식 점검을 반복적으로 수행하는 사용자

### 1.4 비범위 (Out of Scope, 초기 버전 기준)
- 실시간 채팅/커뮤니티 기능
- 이력서 자동 생성(첨삭만 지원, 백지 상태 생성은 후순위)
- 기업 대상 채용 관리 기능 (B2B)
- 모바일 앱 (6단계 이후로 후순위)

## 2. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 데스크탑 프레임워크 | Electron + Next.js (React 19, TypeScript) | 기존 웹 스택 재사용, 모바일 확장 시 UI 로직 일부 공유 가능 |
| 서버/DB/Auth | Supabase (Postgres, Auth, Storage, Edge Functions, pg_cron) | 별도 백엔드 서버 없이 시작 |
| 크롤링 실행 | Supabase Edge Functions(Deno) + pg_cron | 무거워지면 별도 워커(Node/Playwright)로 분리 검토 |
| AI/LLM | Provider 추상화 레이어, 초기 OpenAI 연동 | 이후 Claude 등 교체·병행 가능하도록 설계 |
| PDF 파싱 | pdf-parse / unpdf | 텍스트 추출 후 LLM 전달 |
| 상태관리/폼 | Zustand, React Hook Form + Zod | |
| UI | shadcn/ui + Tailwind CSS | 사이드바 + 멀티 패널 레이아웃 |

## 3. 핵심 기능 요구사항

### 3.1 채용 공고 크롤링 (MVP, 1단계)
- Supabase Edge Function으로 공식 API/RSS 기반 채용 공고 수집
- `pg_cron`으로 1일 1~2회 주기 실행
- URL/고유키 기준 upsert로 중복 방지
- 데스크탑 앱에서 목록 조회: 필터(직무/지역/경력), 검색, 상세 보기
- 크롤링 대상은 이용약관/robots.txt 확인 후 허용된 소스만 사용

**데이터 모델**: `job_postings` (제목, 회사, 링크, 마감일, 태그, 원본 소스, 수집일시)

### 3.2 일정관리 (2단계)
- 메인 화면을 캘린더 중심 대시보드로 구성 (월/주 뷰, 오늘 일정 요약)
- 일정에 메모/설명, 반복 여부, 카테고리(서류마감/면접/스터디 등) 지정
- 채용 공고 마감일을 캘린더에 선택적으로 연동 ("일정에 추가" 액션)
- 메모/체크리스트 입력 UI
- **알림**: Electron `Notification` API로 데스크탑 네이티브 알림
  - 앱 실행 중: 로컬 스케줄러(`node-schedule` 등)로 지정 시각 알림
  - 당일 알림(하루 시작 시 오늘 일정 요약)과 지정 시각 알림 두 가지 트리거 지원
  - 앱 종료 상태 알림 보장은 이후 OS 자동 실행(로그인 시 백그라운드 실행) 옵션으로 검토

**데이터 모델**: `schedules` (제목, 메모, 날짜, 시간, 알림 시각, 반복 여부, 카테고리)

### 3.3 IT 뉴스 크롤링 (3단계)
- RSS 기반 소스(개발 블로그, IT 매체) 우선 수집
- 채용 공고와 동일한 Edge Function + pg_cron 패턴 재사용
- 카드형 뉴스 피드 UI, 북마크 기능

**데이터 모델**: `tech_news` (제목, 요약, 출처, 링크, 발행일)

### 3.4 자소서/포트폴리오 PDF 첨삭 (4단계)
- Storage에 PDF 업로드 → 텍스트 추출 → LLM 첨삭
- 문서 유형별(자소서 문항별/포트폴리오) 프롬프트 템플릿 분리
- 첨삭 결과를 원문 대비 diff/코멘트 형태로 렌더링
- 첨삭 이력 버전 관리

**데이터 모델**: `document_reviews` (원본, 첨삭 결과, 문서 유형, 버전, 생성일시)

### 3.5 CS 면접 퀴즈 (5단계)
- 자체 큐레이션 문제 뱅크로 시작 (네트워크/DB/운영체제/자료구조 등 카테고리)
- 랜덤 출제, 오답노트 기능
- 선택적으로 LLM 기반 꼬리질문/해설 생성

**데이터 모델**: `cs_questions`, `quiz_sessions`, `user_answers`

### 3.6 모바일 확장 (6단계, 후순위)
- 공통 로직(Supabase 클라이언트, 타입, Zod 스키마)을 모노레포 `packages/shared`로 분리
- React Native/Expo로 모바일 앱 개발

## 4. 아키텍처 원칙
- 모노레포 구조(`apps/desktop`, `apps/mobile`, `packages/shared`)로 시작해 모바일 확장 비용 최소화
- 알림 트리거 판단 로직은 플랫폼 독립적으로 `packages/shared`에 두고, 실제 발송(Electron Notification vs. 모바일 Push)만 플랫폼별로 분리
- LLM 프로바이더는 인터페이스로 분리해 교체 가능하게 설계
- 크롤링은 이용약관 준수 우선, 공식 API/RSS 우선 사용

## 5. 단계별 로드맵

| 단계 | 내용 |
|---|---|
| 0단계 | PRD 문서화 + 프로젝트 셋업 (Electron+Next.js 보일러플레이트, Supabase 초기 설정, 기본 레이아웃) |
| 1단계 | 채용 공고 크롤링 + 목록 조회 (MVP) |
| 2단계 | 일정관리 (캘린더 + 메모 + 알림) |
| 3단계 | IT 뉴스 크롤링 |
| 4단계 | 자소서/포트폴리오 PDF 첨삭 |
| 5단계 | CS 면접 퀴즈 |
| 6단계 | 모바일 확장 |

## 6. 검증 방법
- 각 단계마다 `npm run dev`로 Electron 앱 실행 후 end-to-end 기능 확인
- Supabase Edge Function은 `supabase functions serve`로 로컬 테스트 후 배포
- PDF 첨삭은 실제 샘플 PDF로 업로드 → 추출 → LLM 응답까지 수동 테스트
